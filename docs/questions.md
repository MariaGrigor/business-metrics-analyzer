# Контрольные вопросы

## 1. Чем отличается Git от GitHub?

Git — распределённая система контроля версий, которая позволяет отслеживать изменения в проекте, создавать коммиты и ветки.
GitHub — облачная платформа для хранения Git-репозиториев и совместной работы над проектом.

## 2. Для чего используется виртуальное окружение Python?

Виртуальное окружение `.venv` создаёт изолированную среду Python для конкретного проекта. 
Оно позволяет хранить библиотеки и зависимости проекта отдельно от других проектов.

## 3. Что такое commit, branch, remote, pull request?

- Commit — зафиксированная версия изменений в истории проекта.
- Branch — отдельная ветка разработки.
- Remote — удалённый репозиторий, например репозиторий на GitHub.
- Pull Request — запрос на слияние изменений из одной ветки в другую.

## 4. Зачем нужен файл .gitignore?

`.gitignore` определяет файлы и папки, которые Git не должен добавлять в репозиторий.
Например, в этом проекте исключается `.venv`, служебные файлы IDE и временные файлы Python.

## 5. Как организовать командную работу над бизнес-приложением с помощью Git?

Каждый разработчик работает в своей ветке, выполняет изменения, делает commit и отправляет ветку на GitHub.
После этого создаётся Pull Request. Другой участник проверяет изменения, оставляет комментарий или review, 
после чего изменения объединяются с основной веткой `main`.

## 6. Какие файлы обязательно должны быть в репозитории учебного проекта?

В учебном проекте должны быть:
- `.gitignore`;
- `README.md`;
- `requirements.txt`;
- `main.py`.
В репозиторий не должна добавляться папка `.venv`, так как необходимые зависимости перечислены в `requirements.txt`.

## 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?

Если изменения находятся в разных участках файла, Git может объединить их автоматически.
Если разработчики изменили одни и те же строки по-разному, возникает конфликт слияния. 
Его необходимо вручную разрешить, выбрать правильный вариант изменений и затем завершить merge.
